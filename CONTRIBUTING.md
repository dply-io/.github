# Contributing to dply

Thanks for your interest in improving dply. These defaults apply across the
organization's repositories; individual repos may add their own notes.

## Ways to help

- **Report bugs** — open an issue with clear steps to reproduce, what you
  expected, and what happened.
- **Request features** — describe the problem you're trying to solve, not just
  the solution you have in mind.
- **Send pull requests** — for non-trivial changes, please open an issue first
  so we can agree on the approach before you invest the work.

## Pull requests

1. Fork the repository and create a topic branch.
2. Keep changes focused; match the surrounding code style.
3. Include tests where it makes sense, and make sure the existing suite passes.
4. Write a clear PR description: what changed and why.

## Reporting security issues

Do **not** file security vulnerabilities as public issues — see
[`SECURITY.md`](./SECURITY.md).
